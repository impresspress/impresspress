# What a database that reached a supported migration state from a state
# before its block's horizon ends as, after the per-file ledger upgrades it —
# recorded, not judged. `migration_history_tests` (SQLite:
# tests/migration_history.rs; PostgreSQL: impresspress-native's
# tests/postgres_migration_history.rs) rebuilds each case with the runner
# from before the ledger and compares the upgraded schema with a fresh
# install's; a line that moves fails the test.
#
# `<block> <dialect> <state> <path> <outcome>`, where the path is
#   every-state            every state of the block from its first, in order;
#   from-first             the block's first state, then this one directly;
#   from-last-unsupported  the newest state before the block's horizon, then
#                          this one directly;
# and the outcome is
#   converges   the schema equals a fresh install's;
#   residue     it has everything a fresh install has, and the listed extras
#               (tables and columns nothing reads any more);
#   diverges    it lacks what is listed: such a database is adopted and
#               upgraded, but is not what a fresh install is. RELEASE.md's
#               ledger entry names these cases under "Upgraded but not equal
#               to a fresh install", with their remedy;
#   refused     today's runner refuses it by name and changes nothing.
#
# Not recorded, because asserted: a state upgraded straight from its own
# list, and every supported state reached through every supported state
# from its block's horizon, must converge and keep every seeded value.
