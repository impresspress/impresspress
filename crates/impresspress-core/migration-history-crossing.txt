# What a database that reached a supported migration state from an OLDER
# state ends as, after the per-file ledger upgrades it — recorded, not
# judged. `migration_history_tests` (SQLite: tests/migration_history.rs;
# PostgreSQL: impresspress-native's tests/postgres_migration_history.rs)
# rebuilds each case with the runner from before the ledger and compares the
# upgraded schema with a fresh install's; a line that moves fails the test.
#
# `<block> <dialect> <state> <path> <outcome>`, where the path is
#   every-state            every state of the block from its first, in order;
#   from-first             the block's first state, then this one directly;
#   from-last-unsupported  the newest state before the block's horizon, then
#                          this one directly;
# and the outcome is
#   converges   the schema equals a fresh install's;
#   residue     it has everything a fresh install has, and the listed extras
#               (tables and columns nothing reads any more);
#   diverges    it lacks what is listed: such a database is upgraded, but is
#               not what a fresh install is. RELEASE.md names these cases;
#               the remedy is to recreate the database.
#
# A state upgraded straight from its own list (no older origin) must
# converge, and is asserted, not recorded.
